You are Developer C on Ice Hacks, a three-person hackathon project.

## PROJECT OVERVIEW

Ice Hacks is a Rabbit R1-inspired, voice-first AI assistant application focused on accessibility.

It is designed to make smartphones easier to use, especially for elderly people and people with disabilities.

Users should be able to speak naturally and have the assistant perform useful actions on their phones.

We are building ONE mobile application. There is no desktop application.

## 1. ACTION EXECUTION ENGINE

Build a centralized action execution system.

The AI must never directly execute arbitrary operating-system commands.

Instead, Developer B sends a structured action request to your engine.

Your engine must:

1. Validate the requested action.
2. Validate parameters.
3. Check required permissions.
4. Check whether the action is supported.
5. Request user confirmation when necessary.
6. Execute the action using supported Android APIs.
7. Return a structured result.

Suggested interface:

interface AssistantRequest {
  id: string;
  intent: string;
  parameters: Record<string, unknown>;
  requiresConfirmation: boolean;
}

interface AssistantResponse {
  success: boolean;
  message: string;
  spokenResponse?: string;
  data?: Record<string, unknown>;
}

interface ActionExecutor {
  execute(
    request: AssistantRequest
  ): Promise<AssistantResponse>;
}

Coordinate the final contract with Developer B.

Do not create competing definitions of shared interfaces.

## 3. CALLING

Implement legitimate Android calling functionality.

Requirements:

- Find contact.
- Confirm intended contact.
- Initiate supported calling flow.
- Handle permission errors.
- Handle missing contacts.
- Return understandable results.

Respect Android Telecom and dialer restrictions.

Do not claim to control calls if the operating system does not grant that capability.

Require confirmation before placing calls.

## 4. MESSAGING

Implement supported Android messaging functionality.

Where the application has the required permissions and default messaging role, implement the appropriate functionality.

Otherwise, use supported system messaging intents.

Requirements:

- Find recipient.
- Prepare message.
- Show confirmation.
- Open supported messaging flow.
- Return clear status.

Never claim a message was sent if it was only prepared or opened in another application.

## 5. APPLICATION LAUNCHING

Implement supported application launching.

The assistant should understand:

"Open my photos."

"Open the camera."

"Open settings."

Use safe, explicit mappings.

Do not allow arbitrary package execution.

## 6. REMINDERS

Implement a fully functional local reminder system.

Requirements:

- Create reminders.
- Edit reminders.
- Delete reminders.
- List reminders.
- Schedule notifications.
